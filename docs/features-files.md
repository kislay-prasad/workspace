## 9. Files

| | Feature | Where / how |
|---|---|---|
| ✅ | Text and code preview | Documents in a message get a file card (icon by type, name, size, version) with **View**, **Download** and **⋯**. View (or the file's name in the Files tab / Files app) opens the viewer: code and text with line numbers and simple colours (js/ts, py, sh, sql, css, json, html/xml/svg, yaml, ini/toml, markdown, c/java/go/rust/php …), **Wrap lines** switch; `.csv`/`.tsv` as a table with a header row (quoted fields, `;` or tab separators); `.md` rendered with a **Preview / Source** switch. Only the first 256 KB / 5,000 lines / 1,000 rows are loaded (HTTP range request) and a bar says "Showing the first … Download to see the rest". Binary files say they can't be shown. Pictures, PDF, video and audio keep their viewers (PDF/video/audio also open from the Files tab). |
| ✅ | Download as zip | Files tab: select files and/or folders (check boxes, Select all) → **Download as zip**, or **Download all** (the open folder, with its subfolders as zip folders). Files app: select → **Download as zip**. Built on the server with `lib/zip.js` (streamed; stops when the browser goes away). Only files the person may read are included, names are cleaned (no `..`, `/`, `\`, control or bidi characters), duplicates get "(2)". |
| ✅ | Rename or delete your own file (admins any) | File **⋯** (message card, Files tab, Files app) → **Rename** / **Delete**, or the toolbar after selecting. The server allows the uploader or an admin who can see the file. Renames update every message that shows the file (live). Deleting removes the bytes and old versions, and every message shows a dashed "**File deleted**" card with the old name (`m.filesDeleted`). Files used as a profile picture or custom emoji can't be deleted here. |
| ✅ | File details panel | Files tab → **ⓘ** (Details) opens a side panel for the selected file or folder (phones: a dialog); also file **⋯ → Details** and message **⋯ → Details: name** (works for pictures too). Shows type, size, uploaded by, shared date, last new version (when/who), every chat (and folder path) it is in with **Show in chat**, version + **Version history**, active links + **Copy link**, and Open / Download / Rename / Upload new version / Delete. A file on legal hold says so and hides the changing actions. |
| ✅ | Folders | Files tab of any chat or channel: **New folder**, open by clicking, breadcrumb (**Files › Designs › Old**, each part clickable and a drop target), folder **⋯** → Open / Download as zip / Move to / Rename / Delete. Files posted in the chat appear at the top level until moved; Backspace goes up. Deleting a folder never deletes files: its contents move up one level. Up to 300 folders per chat, 8 levels. |
| ✅ | Upload into the Files tab | **Upload** (or drop files from the computer onto the tab or onto a folder) uploads into the open folder without posting a chat message, like Teams. Chat members can open them (the core asks the new `fileRead` hook); they are kept by the hourly clean-up (`keepFile`) and removed with the chat. |
| ✅ | Move files between folders | Drag rows/tiles (several when selected) onto a folder or a breadcrumb part, or **Move to** (toolbar or **⋯**) → folder tree → **Move here**. Anyone who may post in the chat can organise; a folder can't go inside itself. |
| ✅ | Versions | **⋯ → Upload new version** (same kind of file). The file keeps its id, so every message keeps pointing at it and shows the latest name, size and "Version N" (URLs carry `&v=N` so browsers don't show a cached copy). **Version history** lists the current version and older ones (who, when, size) with Open, Download and **Restore** (the restored copy becomes the newest version; nothing is lost). 25 old versions per file. Uploader and admins may add/restore versions; everyone who can see the file can view and download them. |
| ✅ | Share links that expire | **⋯ → Copy link**: who can open it — **People in the chat (signed in)** (default; the link `…/#fl=<secret>` opens the file in the app only for people who can already read it) or **Anyone on this network with the link** (only the uploader or an admin; served by the public route `GET /api/share`, no sign-in) — and for how long: 1 hour, 1 day, 7 days or until a date (5 min – 30 days). The link is copied; the dialog lists the file's active links with Copy and **Remove link**. Files app → **Shared links** lists all my active links. Expired or removed links return a plain "expired or removed" 404 with no file name, and are deleted within 30 s. Public links also stop when their maker loses access or the chat's rules forbid them (`ctx.allowAnyoneLink`, teams area). |
| ✅ | Files app | App bar → **Files** (phones: the bottom bar is full, so it opens from **More apps → All apps**): side column **Recent**, **My uploads**, **Shared links**, and **By chat** (every chat with files). Main area: name search (+ **Search inside files**, which opens chatux's search results on the Files tab, where text-file contents are searched), type chips **All / Documents / Images / Videos / Audio / Archives / Code / Recordings** (`m.recording` messages from the calls area), sort (date, name, size), list or tiles view, select → Download as zip, open, **⋯** (download, copy link, details, show in chat, rename, versions, delete), location link opens the chat's Files tab at that folder. Only files shared in chats you can see (messages or Files tabs) — no avatars, emoji, saved GIFs, voicemail or stray uploads. |
| ✅ | Privacy and limits | Every route checks `canSee` (so the teams area's team, private and shared channel and guest rules apply) + chatux's history limits (`ctx.canSeeMsg`; Files-tab uploads count as sent when uploaded), `fileCanRead`, sizes and rates; legal hold (`hooks.keepMessage`) blocks rename / new version / restore / delete with "This file is on legal hold." (423). |
| ❌ | Editing / co-editing / previewing Word, Excel, PowerPoint; OneDrive / SharePoint | Not possible without those services (as briefed). They download; their icons are coloured by kind. |

## 12. Calendar

| | Feature | Where / how |
|---|---|---|
| ✅ | One calendar for all chats | App bar → **Calendar** (opens in the main area; phones: **More apps → All apps**, and every chat's Calendar tab): events from every chat you are in plus your meetings (`GET /api/meetings` when the meetings area is there; without it only events show). Side column: a mini month (click a day) and **Calendars** check boxes (Meetings and each chat) to hide/show. |
| ✅ | Views and navigation | **Day / Work week / Week / Month** picker, **Today**, ‹ ›, and the range title (▾) opens a date picker. Red current-time line (moves every minute). Clicking a day header or a month day opens that day. Phones start in Day view. |
| ✅ | All-day and repeating events | Event form: **All day**; **Repeat**: every day, every weekday, weekly on chosen days (M T W T F S S buttons), monthly (same date, short months skipped), yearly (29 Feb only in leap years), every N days/weeks/months/years; **Ends**: never, on a date, after N times. Editing a repeating event edits the series (the form says so); event card → **Delete → Delete this occurrence / Delete the series**. All-day events land on the same date for everyone. |
| ✅ | Time zones | Each event stores its time zone (form: **Time zone**, default yours; repeats keep their wall-clock time across daylight-saving changes); everything is shown in your zone and the card adds the event's own time when it differs. **⋯ → Second time zone** adds a second hour column in day/week views (saved for you). |
| ✅ | Drag to move | Day/week: drag an event to another time or day (15-minute steps), drag its bottom edge to change the end; month: drag an event to another day. Only the creator or an admin can (others don't get the handle and the server refuses with 403); moving a repeating event asks and moves the whole series (deleted occurrences move along). Live updates wait until you let go. |
| ✅ | Colour categories | Six colours. **⋯ → Categories** renames them for yourself; event card → **Categorize** (also for meetings) or the form's **Category**. Categories are personal (like Outlook): others don't see your colours. |
| ✅ | New meeting / New event | **New meeting** calls `LC.meetings.schedule({ start, end })` (meetings area form with invitees); click or drag on an empty slot → a small menu **New meeting / New event** prefilled with that time (double-click a month day). Without the meetings area these create an event in a chosen chat. **New event** asks which chat; a chat's tab uses that chat. |
| ✅ | Accept / Tentative / Decline | Meetings: through `POST /api/meetings/rsvp` (meetings area). Events: an answer per person stored on the event (`rsvp`), shown to everyone in the chat on the card ("Accepted (2): …"); declined events are struck through, tentative ones hatched; the creator gets an Activity item ("Bob might come to …", registered in `LC.ext.activityTypes.event`). People who declined get no reminder. |
| ✅ | Join | Card → **Join** on meetings (`LC.meetings.join(id)`) and on events with **Online: join with this chat's call** (`LC.startCall(chat, 'video')`, which joins a running call). Events and meetings happening now (from 15 min before) also show **Join** on the block and in the tab's Upcoming list. |
| ✅ | Scheduling assistant | **⋯ → Scheduling assistant**: pick people and a day → a 7:00–21:00 grid of busy (and tentative) blocks per person and an "All selected" row; click a free slot → **Schedule** opens New meeting (with them invited) or New event. `GET /api/freebusy` counts events people created or accepted and meetings they are invited to (not declined); titles only for chats/meetings you are in. |
| ✅ | .ics export and import | **⋯ → Export calendar (.ics)** (everything you see incl. your meetings) or, in a chat's tab, that chat's events. **⋯ → Import an .ics file…** into a chat: VEVENT with SUMMARY, DTSTART/DTEND/DURATION (dates, UTC, TZID, floating = your zone), RRULE (DAILY/WEEKLY/MONTHLY/YEARLY, INTERVAL, COUNT, UNTIL, BYDAY for weekly/weekdays), EXDATE, DESCRIPTION, LOCATION; cancelled events skipped; folded/escaped text handled. |
| 🟡 | Rule coverage | Monthly/yearly rules by weekday ("2nd Tuesday", `BYDAY=2TU`), `BYMONTHDAY`, `BYSETPOS` … are imported as single events (the toast counts them). Editing one occurrence on its own isn't offered (edit = whole series; delete one occurrence works). Export writes repeating timed events with `TZID=<IANA name>` and no VTIMEZONE block (Google/Apple accept it; older Outlook may not). |
| ✅ | Per-chat Calendar tab | The chat's **Calendar** tab uses the same calendar (month view by default, all views, drag, card, RSVP, categories, export/import for that chat) plus an **Upcoming** list (next 60 days) with Join / Edit. **Add event** adds to that chat. |
| ✅ | Reminders | Per occurrence (repeating events remind every time), "⏰ … starts in N min" line in the chat + `reminder` event; old events keep working and the old tick in `routes-collab.js` is kept away from calendar events (`reminded: true`), so nothing fires twice. |
| ❌ | Live sync with Outlook / Google Calendar | Needs those cloud services (as briefed); use .ics export/import. |
